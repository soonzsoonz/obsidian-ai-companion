# AI Companion

【[English](../README.md) | 繁體中文 | [简体中文](README.zh-CN.md) | [Français](README.fr.md) | [Deutsch](README.de.md) | [Español](README.es.md) | [Italiano](README.it.md) | [Português (BR)](README.pt-BR.md) | [日本語](README.ja.md) | [한국어](README.ko.md) | [हिन्दी](README.hi.md) | [Indonesia](README.id.md)】

一個 Obsidian 外掛，讓 AI 真正參與你的日誌 —— 務實、貼近生活，不是心靈導師。

你照原本的方式寫日誌，照原本的方式用手機分享連結。外掛會讀這兩者，用具體的話回應你，
把連結整理成當天的簡報，並逐步累積它對你的認識，讓建議愈來愈貼合你的狀況。

## 功能

**日誌回饋** — 讀你寫的東西，用該用的口吻回應：🫂 吵架時是心靈導師、🎒 孩子的事是學校老師、
🔧 程式問題是技術顧問。每則回應開頭會標上該角色的表情符號和名稱，所以一天裡混雜的三件事
讀起來就是三則回應，而不是一整面文字。什麼情境用什麼角色是設定裡一張可編輯的表，
每個角色的表情符號、名稱、指示也都能改。

**新知彙整** — 用手機把 Threads、X、Facebook 的貼文分享進 vault，其餘外掛處理：
它會把連結列進轉貼區，再依內容寫成摘要。開啟研究模式時會實際抓取每個頁面，
依它真正寫了什麼來摘要，而不是從標題猜。人存東西的理由很多 —— 工作要用、想自己試試、
家人可能用得上，或單純覺得好 —— 所以摘要只講你能拿它做什麼，不會評價它重不重要。

**完整報告** — 當某一項值得展開時，AI 會在當天的資料夾另外寫一篇筆記：這是什麼、怎麼做、
要注意什麼，並把方法逐字引用下來，讓你不用回頭開原文就能直接用。彙整那一條會連過去。
每次執行有數量上限，也可以關閉。

**事實表** — AI 會把關於你的長期事實（人、專案、目標、反覆出現的問題）累積在一則
一般的、可編輯的筆記裡，其他功能回答前都會先讀它。事實是以**現況**陳述並隨變化改寫，
所以寫了幾個月之後仍然好讀，不會長成一份流水帳。

## 一天怎麼運作

1. 白天用手機把連結分享到落地資料夾。
2. 寫你的日誌 —— 只要寫「日誌」那一區，其餘會幫你補上。
3. 執行**產生新知彙整**。你的分享會出現在轉貼區、摘要出現在彙整區，分享檔則移到歸檔。
4. 想要回應時，執行**產生日誌回饋**。

或者設定排程，讓第 3、4 步自己發生。

## 每日筆記版面

第一區和第三區是你的，第二區和第四區由 AI 寫。

```markdown
## 日誌
- 今天做了什麼

## AI回饋
- （AI 寫在這，附時間戳）

## 今日社群轉貼
- （AI 把你分享的連結列在這）

## AI整理社群新知
- （AI 寫在這，附時間戳）
```

標題會跟著 Obsidian 的介面語言走，所以英文介面寫的是 `## Journal`、`## AI Feedback`。
用某個語言寫的筆記換到另一個語言仍然可用：比對時認得所有語系的標題，而既有區塊會保留
它原本的標題，不會被改寫。

區塊是靠標題定位的，所以它們在檔案裡的順序不影響運作。重跑指令會附加一段新的、
帶時間戳的內容，而不是覆蓋先前的，所以一天跑好幾次會累積下來。四個標題以外的東西
永遠不會被動到。

## 資料夾結構

```
ai-companion/
  journal/              每日筆記；每天可以有自己的同名資料夾放報告
  news/
    landing/            ← 手機分享請選這個資料夾
    archived/           處理完的分享會搬到這
  memory/
    facts.md            AI 對你的了解 —— 可自由編輯
    _log.md             唯讀附加的更新紀錄
```

每個資料夾都可以在設定裡改。外掛載入時會自動建立，所以你在手機分享時就已經選得到
落地資料夾了。

## 安裝

需要桌面版 Obsidian 1.5.0 以上。

1. 從最新的 release 下載 `main.js`、`manifest.json`、`styles.css`。
2. 放進 `<vault>/.obsidian/plugins/ai-companion/`。
3. 在「設定 → 第三方外掛」啟用 **AI Companion**。
4. 到「設定 → AI Companion」設定你的 AI CLI。

### 設定 CLI

外掛會把 prompt 交給本機的 AI CLI 並讀取它的輸出，所以那個指令必須能非互動執行。
從下拉選單選好你的 CLI，需要的參數就會自動帶入 —— **路徑通常留空即可**，
外掛會去常見的安裝位置找。只有當它找不到時才需要自己填。

| CLI | 狀態 |
| --- | --- |
| Claude Code | 已驗證；prompt 走 stdin，研究模式可用 |
| Antigravity (`agy`) | 已驗證；prompt 當引數傳入 |
| Codex (ChatGPT) | 有提供但未實測 —— 歡迎回報結果 |

若指令回報沒有輸出，多半是那個 CLI 想進入互動模式，請檢查「額外參數」欄位。

**Antigravity 的研究模式有限制**：agy 在非互動模式下無法核准網路權限，要開啟研究模式
需要在它的 `settings.json` 加上 allow-rule。不需要抓網頁的功能則完全正常。

### 從原始碼建置

```bash
npm install
npm run build
```

## 指令

以下都在指令面板裡，也在左側功能區圖示的選單中。日誌筆記的右鍵選單則提供針對**那一天**
重跑的選項。

| 指令 | 做什麼 |
| --- | --- |
| 建立今日日誌 | 依範本建立今天的筆記並開啟 |
| 產生日誌回饋 | 用該用的口吻回應當天的日誌 |
| 產生新知彙整 | 列出你的分享並逐則寫成摘要 |
| 累積事實表 | 從當天的日誌更新事實表 |
| 開啟事實表 | 打開 `facts.md` 閱讀或修正 |
| 歸檔已處理的轉貼 | 清掉中斷執行留下的殘留 |

會寫入日誌筆記的指令，在你打開非日誌筆記時會停用，所以它們不會動到你沒打算改的檔案。

## 設定

- **AI** — 選你的 CLI（Claude Code、Antigravity、Codex），需要的參數會自動填好；
  或選「自訂」。另有路徑、額外參數、模型、推理強度、逾時時間。
- **日誌** — 資料夾、日期格式、範本路徑（支援 `{{date}}` 和 `{{time}}`）。
  自訂範本必須保留那四個標題，AI 是靠它們定位的。
- **新知** — 落地與歸檔資料夾、研究模式開關、歸檔保留天數（0 表示永久保留）。
- **排程** — 手動（預設）、開啟時、或每 N 小時，並可分別勾選排程要跑彙整、回饋、或兩者。
- **角色** — 情境→角色對應表，以及每個角色的指示。內建項目可個別恢復預設，
  也可以新增自己的情境和角色。
- **外觀** — 為外掛自己的區塊選一個樣式（卡片／低調／雜誌），預設關閉且只套用於日誌筆記。
  樣式只在閱讀模式生效；所有數值都取自 Obsidian 的 CSS 變數，所以你的主題仍然說了算。

### 關於排程

排程只在 Obsidian 開著時執行 —— 以 CLI 為基礎的外掛沒有背景程序，錯過的時段會在
下一次觸發時處理，而不會補跑。

新知彙整適合排程，因為每次處理的都是新到的分享。日誌回饋在排程中預設關閉：
每次執行都會附加一段新的回饋，一天跑六次會讓那一區塞滿幾乎相同的建議。

## 隱私與安全

啟用任何功能前請先讀這一段。

- **你的日誌會被送到 AI 供應商。** 外掛啟動本機的 AI CLI 並把日誌文字交給它。
  那個 CLI 接下來把資料送去哪、送給誰，是由那個工具決定，不是這個外掛。
  日誌裡有健康狀況和家人的事，請審慎選擇。
- **AI 會直接寫入你的 vault**，沒有確認步驟。它只寫上面列出的那些區塊，但寫的時候不會問你。
- **保留溯源紀錄。** `memory/_log.md` 是唯讀附加的，記錄每次事實更新來自哪一天的日誌，
  讓你能分辨哪些是你寫的、哪些是 AI 推論的。
- **事實表是你的，可以自己改。** AI 記錯了就打開改掉，下次執行會以你改過的版本為準。
  但要注意 AI 每次都會重寫整份檔案，所以日誌裡沒有依據的內容不一定會留下來。
- **排程預設為手動。** 無人看管、會寫進你 vault 的執行，應該是一個決定，而不是預設值。
- **歸檔刪除需自行開啟**，且走系統資源回收筒，可以救回來。
- **僅限桌面版。** 啟動 CLI 需要 Node，所以無法在手機上執行。但**從手機分享進 vault**
  完全沒問題 —— 那是 Obsidian Sync 在做的事。

## 多語系

介面提供 22 種語言，跟隨 Obsidian 自己的語言設定：阿拉伯文、德文、英文、西班牙文、
波斯文、法文、印地文、印尼文、義大利文、日文、韓文、荷蘭文、波蘭文、葡萄牙文、
巴西葡萄牙文、俄文、泰文、土耳其文、烏克蘭文、越南文、簡體中文、繁體中文。

翻譯放在 `src/i18n/locales/`。每個語系都以英文為型別依據，所以少一個 key 會編譯失敗，
而不是靜默退回英文。
